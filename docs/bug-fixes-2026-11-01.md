## Fixed behavior

1. **Shop charges:** purchases now run inside transactions and use a persisted request ID. Retrying a freeze purchase after a lost response reuses that ID. Simultaneous cosmetic requests cannot charge repeatedly for an already owned item. Monthly Pro eligibility and the debit are checked in the same transaction. Request IDs cannot be reused to purchase a different item.
2. **Account deletion:** active opponents receive their entry fees back before duel records are removed. Deletion can be retried without refunding twice. Firebase deletion failure returns a retryable error rather than success, and the account is blocked from normal operations while deletion is pending. A deletion retry after Firebase has already removed the user accepts the still-valid signed identity token only for the missing-user case; revoked tokens cannot delete an existing account. Daily reward records, purchase receipts, and account-specific phone caches are included in cleanup.
3. **Upload queue:** permanent 400/422 validation failures are moved into a persisted rejected-results collection. The original result and server reason remain on the phone, and later valid results continue uploading. Network failures, authentication failures, rate limits, and server failures remain retryable. A manual retry can return rejected records to the queue.
4. **Daily reset:** the first valid account time zone is pinned on the backend and reused by Android, offline projection, and Home's challenge counters. Changing the phone's zone cannot repeatedly reset the server quota. On first use of a day ledger, existing results for that local day are included to avoid an extra allowance during migration. Onboarding supplies the time zone, and settings refresh immediately when onboarding completes.
5. **Paid Pro confirmation:** a successful store transaction is distinguished from verified Pro activation. Pending verification is persisted per account and retried on launch, foregrounding, and a timer without buying again. ProScreen reports pending confirmation instead of claiming everything is unlocked. Restore distinguishes confirmed, pending, failed, and no-purchase cases. Actual store integration still requires the RevenueCat key that is currently empty.

Additional correctness work:

- Server validation uses the configured challenge window and selected apps, with settings history for delayed results rather than always applying the newest difficulty to an old event.
- Active Android challenges retain their original window across settings changes and restarts.
- Screen-off and activity-pause events participate in foreground/exit detection; locking the phone can count as leaving the distracting app.
- Native account cleanup runs on the main thread and stops further ticks before clearing queued results.
- Home counts only results that count toward the daily allowance. The layout was not redesigned.

Stronger device authenticity requires a separate attestation integration and service configuration. No hardcoded client secret was added as a substitute.
